# BSOD Dump Analyzer

Локальная Windows-программа для поиска и анализа crash dump после BSOD. Главная
цель проекта — не просто показать STOP-код, а **максимально честно разделить
факты, гипотезы и ограничения**, затем выдать адресный план проверки и только
безопасный, журналируемый Autofix.

## Главные принципы

1. **Локальный анализ — основной продукт.** ИИ не требуется для диагноза,
   рекомендаций или Autofix.
2. **ИИ выключен по умолчанию.** Включается отдельной галочкой в настройках;
   после выключения кнопки и вкладка ИИ исчезают, CLI больше не обнаруживаются.
3. **Один ярлык WinDbg не равен доказанному виновнику.** `Probably caused by`,
   `IMAGE_NAME`, `MODULE_NAME`, символы, стек и bucket сопоставляются как
   независимые сигналы.
4. **Системные посредники не объявляются корнем проблемы на автомате.** Например,
   `ntoskrnl.exe`, `ntkrnlmp.exe`, `hal.dll`, `Wdf01000.sys`, `ndis.sys`,
   `tcpip.sys`, `storport.sys`, `dxgkrnl.sys` и `memory_corruption` часто лишь
   оказываются в месте проявления повреждения.
5. **Уверенность — качество доказательств, не выдуманная вероятность.** Отчёт
   объясняет, что подтверждает гипотезу и что мешает ей доверять.
6. **Autofix не должен ухудшить загружаемость системы.** Автоматически доступны
   только фиксированные read-only/low-risk команды из allow-list; каждое действие
   пишет stdout, stderr, exit code, длительность и результат проверки.

## Возможности

- поиск дампов в `C:\Windows\Minidump`, `C:\Windows\MEMORY.DMP`,
  `LiveKernelReports`, `%LOCALAPPDATA%\CrashDumps`, WER и пользовательских папках;
- корректный разбор `DUMP_HEADER64`, `DUMP_HEADER32` и защищённый разбор
  user-mode `MINIDUMP`/`ExceptionStream`;
- глубокий анализ через `cdb.exe` из Debugging Tools for Windows;
- команды `!analyze -v`, `.bugcheck`, `kv 40`, blackbox-разделы и
  bugcheck-специфичные запросы (`!errrec`, `!irp`, `ln`);
- дополнительный безопасный `lmvm` для подтверждённого стороннего токена модуля;
- извлечение process, image/module/symbol, bucket/hash, стека, качества символов,
  метаданных драйвера, exit code, таймаута и длительности сеанса;
- сверка STOP-кода и параметров из заголовка с `.bugcheck`;
- локальный evidence-based диагноз: основная гипотеза, категория, качество,
  доказательства, факторы неопределённости, альтернативы и ограничения;
- адресный план по категориям driver/GPU/storage/memory/hardware/
  system-corruption/application/unknown;
- **корреляция серии дампов**: повторяемость одного модуля в нескольких
  независимых падениях усиливает подозрение (сознательно без перевода счётчика
  в «вероятность»), с исключением системных посредников;
- контролируемый Autofix с JSON и текстовым отчётом;
- опциональное второе мнение через Claude Code, Codex CLI, Grok CLI либо
  копирование подготовленного промпта.

## Требования

- Windows 10/11 для реального поиска системных дампов и Autofix;
- Python 3.8+;
- рекомендуется **Debugging Tools for Windows** (`cdb.exe`) из Windows SDK;
- ИИ-CLI нужны только после добровольного включения ИИ-функций.

## Быстрый старт (git clone → сразу пользоваться)

Внешних зависимостей нет — только стандартная библиотека Python (`tkinter`
входит в поставку Python для Windows). Ничего ставить через `pip` не нужно.

```bat
git clone <URL-репозитория>
cd misc
python run_analyzer.pyw
```

После анализа отдельных дампов кнопка **«🔗 Корреляция серии»** разберёт все
найденные дампы и покажет, какой сторонний модуль повторяется в нескольких
падениях — это более сильный сигнал, чем один дамп.

## Как читать результат

Вкладка **«Отчёт»** идёт в следующем порядке:

1. достоверно извлечённые факты;
2. основной локальный вывод;
3. доказательства;
4. факторы, снижающие уверенность;
5. альтернативные гипотезы;
6. типичный фон по STOP-коду — явно помеченный как справка, а не диагноз;
7. ограничения конкретного дампа.

Вкладка **«Что делать»** строится по категории, а не по универсальному шаблону.
Например, `chkdsk /scan` появляется для storage-сценария, а DISM → SFC — только
когда локальный диагноз указывает на повреждение компонентов Windows.

## Autofix и отчёты

Autofix разрешает действие лишь при одновременном выполнении условий:

- шаг явно помечен как автоматический;
- риск `read-only` или `low`;
- ID шага и **точная строка команды** совпадают со встроенным allow-list;
- команда не содержит запрещённых опасных операций.

Для каждого запуска создаётся каталог:

```text
%LOCALAPPDATA%\BSODAnalyzer\reports\<timestamp_id>
```

Внутри сохраняются:

- `manifest.json` — что планировалось выполнить;
- `run_autofix.ps1` — точный неизменяемый сценарий запуска;
- отдельные `*.stdout.txt` и `*.stderr.txt`;
- вывод проверочных команд;
- `summary.json` и `summary.txt` с итогами.

**Никогда не выполняются автоматически:** Driver Verifier, DDU, удаление или
принудительная замена драйверов, BIOS/UEFI и firmware, `chkdsk /f /r`, операции
с загрузчиком, форматирование, произвольный rollback.

## Опциональный ИИ

Откройте **Настройки → Опциональный ИИ** и поставьте галочку. Только после этого:

- создаётся AI runner и выполняется поиск доступных CLI;
- появляются выбор бэкенда, кнопка второго мнения и вкладка ответа;
- становится доступно копирование рецензионного промпта.

Снятие галочки сразу скрывает эти элементы и освобождает AI runner. Настройка
`ai_enabled` отсутствует или равна `false` — значит ИИ выключен.

ИИ получает уже готовый локальный диагноз и инструкцию **проверить его**, а не
подменить. API-ключи проект не использует.

## Структура

```text
bsod_analyzer/
  bugcheck_db.py    локальный справочник STOP-кодов
  dump_finder.py    поиск и удаление дампов
  dump_parser.py    заголовки, CDB/WinDbg, структурированные факты
  diagnosis.py      evidence-based гипотезы и оценка качества
  correlation.py    корреляция серии дампов (повторяемость модулей/bucket)
  report.py         отчёт и опциональный рецензионный промпт
  remediation.py    адресные планы и Autofix allow-list
  autofix.py        elevated PowerShell, логи и проверка результатов
  ai_backends.py    опциональные CLI-бэкенды
  config.py         безопасные настройки и миграция старого config
  gui.py            Tkinter UI и динамическое включение ИИ
CLAUDE.md            передача контекста следующему разработчику/агенту
tests/               регрессии парсера, диагноза и безопасности
```

## Честные ограничения

- Один minidump может показать только место последнего падения. Следующий большой
  прирост точности даст корреляция серии дампов по bucket/hash/модулям/стекам.
- Связь `.sys → service → INF → Driver Store → PnP device` пока не полностью
  автоматизирована; поэтому изменение драйвера остаётся ручным.
- Оценка доказательств — детерминированная эвристика, которую нужно расширять на
  реальных обезличенных дампах и adversarial fixtures.
- Без корректных символов и достаточно полного дампа программа сознательно
  снижает качество вывода вместо уверенного гадания.
